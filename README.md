# Гейт расширений 1С

**Гейт расширений 1С.** Он стоит между поставкой расширений (своих или подрядчика) и рабочей базой. Гейт загружает комплект в тестовую базу и выдаёт **зелёный**, **жёлтый** или **красный** вердикт. Обновлением рабочей базы управляет оператор в отдельном режиме. При выпуске с красным вердиктом гейт записывает указанную оператором причину в отчёт.

Сделано для 1С:Предприятия 8.3 на Windows: кластер или файловая база, БСП в конфигурации. Типовая конфигурация не трогается, работа идёт только с расширениями и внешними обработками.

## Зачем

Расширения ломаются тихо: перехват метода, которого в новой версии типовой уже нет; модуль, который не компилируется; форма, которая не открывается; документ, который перестал проводиться. Подрядчик прислал `.cfe` с припиской «всё проверили», а узнаёшь об этом от пользователей. Гейт ловит такое до рабочей базы и показывает только новое: известные замечания лежат в эталоне и вердикт не портят.

## Что проверяется

- **Конфигуратор:** проверка конфигурации и применимости расширений (`/CheckConfig`, `/CheckCanApplyConfigurationExtensions`), при желании синтаксис-контроль.
- **Канарейка:** под каждым пользователем из списка запускается сеанс и проверяется, что расширения в нём применились.
- **Самопроверка:** обработка «Выполнить после обновления» прогоняется до загрузки и после, «после» сравнивается с «до». Она проверяет компиляцию модулей расширений, создание форм, операции со справочниками и документами, перепроведение и отмену проведения (в транзакции, которая всегда отменяется) и сценарии доработок вашей базы.
- **Внешние обработки** (`.epf`, `.erf`, выгрузки в файлы) записываются в справочник «Дополнительные отчёты и обработки» через БСП. После записи проверяется, что обработка подключается и её формы создаются.
- **Снимки «до/после»:** сообщения обмена, движения документов после перепроведения, печатные формы, отчёты на СКД. Изменился снимок — жёлтый, разница в файле.
- **Карта покрытия:** что добавили расширения (перехваты, формы, подписки, регламентные задания) и чем это задето в самопроверке; новое непокрытое — жёлтым.
- **Время ключевых операций** против истории прогонов: заметно медленнее — жёлтое.
- **Ночной прогон** «как есть» по расписанию Windows (`nightly.cmd -Install`).
- **Откат на тестовой базе.** При красном или жёлтом вердикте с замечаниями оператор выбирает, оставить комплект или откатить. При откате гейт восстанавливает прежние версии расширений и обработок, новые расширения удаляет по имени.
- **Модульные тесты и действия.** Гейт запускает YAxUnit на тестовой базе и сохраняет JUnit. Если комплект содержит действия после обновления, гейт выполняет их до самопроверки «после» и сохраняет проверенный исполнитель для выпуска.

Плюс экран `ci.exe` с планом прогона и ходом каждого шага, статистика длительностей, разбор прогона (`report.txt`), обновление и откат рабочей базы.

## Установка

1. Скачай `ci-gate_<версия>.zip` из [Releases](https://github.com/hleserg/1c_tiny_exctetions_gate/releases) (или собери сам, см. ниже) и распакуй.
2. Запусти `install.cmd` и ответь на вопросы:
   - папка установки (по умолчанию `C:\ci`);
   - платформа 1С;
   - тестовая база;
   - рабочая база;
   - расширения;
   - под кем запускать конфигуратор.

   Установщик пишет `config.psd1` и собирает обработки в `tools` конфигуратором тестовой базы. Ещё он добавляет папку в `PATH` пользователя, права администратора для этого не нужны.
3. Новое окно PowerShell. Набери `ci` — откроется экран с меню. Или `gate` — тот же гейт в консоли.

Перед первым прогоном на настоящей базе стоит выполнить `test.cmd`: он прогоняет гейт с подставной 1С, без баз и кластера.

Полное руководство — [gate/readme.txt](gate/readme.txt). Оно же лежит в папке установки.

## Сборка из исходников

Для полной сборки нужен Go 1.24.7 или новее. Версию для CI задаёт [src/ci-tui/go.mod](src/ci-tui/go.mod).

Публичный комплект собирается из корня репозитория.

```powershell
.\build.cmd
```

Для комплекта площадки передай полный путь к каталогу с её пакетами.

```powershell
.\build.cmd -private (Resolve-Path ..\мой-приватный-репо).Path
```

Архивы появятся в `dist/`.

Для первого запуска из исходников начни с разбора скриптов и сборки в памяти. Команды приведены в [инструкции разработчика](docs/development.md). Устройство прогона описано в [архитектуре](docs/architecture.md), подключение сценариев своей базы — в [руководстве по пакетам](docs/packages.md).

## Структура

| Папка | Что там |
|---|---|
| `gate/` | скрипты гейта (PowerShell 5.1), образец настроек, руководство, тесты без 1С |
| `src/ci-tui/` | экран `ci.exe` (Go, Bubble Tea) |
| `src/fake1c/` | подставная 1С для тестов |
| `src/merge1c/` | объединение исходников при приёмке поставок |
| `src/build/` | сборщик архивов и обработок |
| `epf/` | обработки в виде выгрузки в файлы: ядро «Выполнить после обновления» и канарейка |
| `packages/` | пакеты сценариев самопроверки; в репозитории — пример |
| `docs/` | устройство, пакеты, разработка, планы |
