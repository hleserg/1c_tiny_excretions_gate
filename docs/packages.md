# Пакеты сценариев самопроверки

Обработка «Выполнить после обновления» состоит из **ядра** и **пакетов**.

- **Ядро** (`epf/ВыполнитьПослеОбновления`) годится для любой конфигурации на БСП. В нём журнал, шаги и задания, окружение, проверка применимости, компиляция модулей, операции со справочниками и документами, формы, перепроведение и отмена проведения в отменяемой транзакции.
- **Пакет** (`packages/<Имя>`) — всё про конкретную базу:
  - какие расширения «наши»;
  - списки их объектов;
  - ожидаемые версии;
  - свои шаги и сценарии доработок;
  - свои кнопки формы.

Свой пакет обычно лежит в **приватном репозитории** площадки. Сборка с ним: `build.cmd -private <папка>`.

## Состав пакета

| Файл | Что | Обязателен |
|---|---|---|
| `package.json` | `{"name": "<Имя>", "title": "...", "order": 10}`: имя (= папка, идентификатор 1С), представление, порядок выбора | да |
| `ObjectModule.bsl` | служебная часть модуля объекта: крючки и свой код | да |
| `ObjectInterface.bsl` | экспортные функции модуля объекта, которые вызывает форма | нет |
| `FormModule.bsl` | служебная часть модуля формы | нет |
| `FormCommands.bsl` | обработчики команд формы пакета | нет |

Сборщик вставляет каждый файл на свою метку `// @@ПАКЕТЫ: ...@@` ядра. Части модулей оборачиваются в `#Область Пакет<Имя>`. Если у команды формы (`Form.xml`) нет обработчика ни в одном пакете, на её место встаёт заглушка с предупреждением.

## Крючки

Функции с суффиксом имени пакета. Обязательна только `ПакетПодходит<Имя>(Причина)`. Остальные сборщик подключает, если они есть.

| Крючок (функция пакета) | Что возвращает / делает |
|---|---|
| `ПакетПодходит<Имя>(Причина)` | Булево: пакет подходит к базе; в `Причина` — почему. Выбирается первый подошедший по `order` |
| `ДобавитьШагиПакета<Имя>(Шаги, Место)` | свои шаги (`ДобавитьШаг`) в места `ПослеОкружения`, `ПослеПрименимости`, `ПослеКомпиляции`, `ПослеОпераций` |
| `ВыполнитьШагПакета<Имя>(ИмяШага, ЭлементШага)` | выполнить свой шаг; Ложь — такого шага нет |
| `ЭлементыШагаПакета<Имя>(ИмяШага)` | элементы шага, который идёт по частям, или Неопределено |
| `ПредставлениеШагаВнеПрогонаПакета<Имя>(ИмяШага)` | название шага, который вызывает кнопка формы |
| `ОбъектыПакета<Имя>(Вид)` | имена объектов расширений для механизмов ядра: `ОбщиеМодули`, `МодулиОбъектов`, `МодулиМенеджеров`, `МодулиНаборовЗаписей`, `Формы`, `ДокументыДляПерепроведения` |
| `НашиРасширенияПакета<Имя>()` | имена наших расширений (их ошибки — ошибки, а не предупреждения) |
| `ПометкаНашихРасширенийПакета<Имя>()` | слово в текстах записей: «в коде расширений<слово>» |
| `ПрефиксыНашихОбъектовПакета<Имя>()` | префиксы имён наших объектов |
| `ПояснениеКомпиляцииПакета<Имя>()` | что шаг компиляции не проверяет и почему |
| `ОкружениеПакета<Имя>(ИменаРасширенийБазы, ИменаРасширенийСеанса)` | своя часть шага «Окружение» |
| `РегистрыСОбъяснимымиРасхождениямиПакета<Имя>(ИмяДокумента)` | регистры, расхождения в которых после перепроведения объясняет пакет |
| `ПодготовкаПерепроведенияПакета<Имя>()` | свои сведения в начале перепроведения |
| `УзлыДляСнимковОбменаПакета<Имя>()` | узлы обмена для шага «Обмены»: Массив из Структура (Узел, Имя) |
| `ОбъектыДляСнимковОбменаПакета<Имя>(Узел, ИмяУзла)` | объекты, для которых строится сообщение обмена по узлу |
| `СрезыОбменаПакета<Имя>(Узел, ИмяУзла)` | срезы шага «Обмены»: по объекту на каждый путь данных узла (вид операции, договор пуст или заполнен и т.п.) — Массив из Структура (Ссылка, Срез). Очередь узла ядро собирает само |
| `ДокументыДляСнимковДвиженийПакета<Имя>()` | виды документов, движения которых после перепроведения уходят снимком в гейт |
| `ПечатныеФормыДляСнимковПакета<Имя>()` | шаг «Печатные формы»: Массив из Структура (Документ, Команд) |
| `ОтчетыДляСнимковПакета<Имя>()` | шаг «Отчеты»: Массив из Структура (Имя, Параметры) |
| `СценарииПакета<Имя>()` | шаг «Сценарии»: Массив из Структура (Имя, Представление, ТЗ) |
| `ВыполнитьСценарийПакета<Имя>(ИмяСценария, Результат)` | выполнить сценарий в отменяемой транзакции ядра (свои транзакции не открывать); итог — в Результат: Выполнен, Успех, Текст, Пропуск |
| `ПриСозданииНаСервереПакета<Имя>()` (форма) | что форма делает при создании |
| `ЗаписатьСтатьюБазыЗнанийПакета<Имя>()` (форма) | статья в базу знаний (режим `kbarticle`) |
| `КомандыФормыПакета<Имя>()` (форма, `&НаСервере`) | кнопки пакета: Массив из Структура (Имя, Заголовок, Действие). Форма создаёт команды и кнопки кодом; обработчик `Действие` — процедура `&НаКлиенте` из `FormCommands.bsl` пакета |

Внутри пакета доступны функции журнала ядра:
- запись в журнал: `ЗаписатьОК`, `ЗаписатьОшибку`, `ЗаписатьВнимание`, `ЗаписатьПропуск`, `ЗаписатьИнфо`, `Проверить`;
- проверки разрешений: `ЗаписьРазрешена`, `ПроведениеРазрешено`;
- данные: `ПоследняяСсылка`, `ПараметрыЗапуска` и остальное ядро.

Имена своих служебных процедур должны быть уникальными на всю сборку. Удобно начинать их с имени пакета.

## С чего начать

Скопируй `packages/Пример` в `packages/<ИмяБазы>` своего приватного репозитория. Переименуй функции: суффикс `Пример` → имя пакета. Поправь `ПакетПодходит<Имя>` — обычно пакет узнаёт базу по своему расширению. Списки объектов удобно генерировать из выгрузки расширения в файлы.

Проверка: `build.cmd -private <папка> -check`.

## Правило про тексты записей

Гейт сравнивает журнал «после» с «до» и с эталоном по текстам записей `[ОШИБКА]`, `[ВНИМАНИЕ]`, `[ПРОПУСК]`, `[ОК]` и по ключам заданий. Поменял текст записи — у всех, у кого уже есть эталон, старая запись «пропадёт», а новая «появится». Тексты меняются только намеренно, с пометкой в истории руководства.
