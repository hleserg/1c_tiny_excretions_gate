# Что видит оператор гейта

Аудит от 27 ноября 2026 года. Исходная версия ядра — `605fbb9`. Проверены подписи меню, диалогов и журналов по коду их обработчиков. Сверка с Git, решение по комплекту, ручное обновление, ночные сценарии, откат, история и ожидание CI проверены автоматическими тестами. Экраны терминала проверены на нескольких размерах окна.

## Что исправлено

| Где | Что видел оператор | Что теперь видно |
|---|---|---|
| Сверка перед загрузкой из Git | После трёх выгрузок расширений слева появлялось «3/3, 100%». Внизу шла ещё одна выгрузка. | Слева «Расширения выгружены · 3 из 3». Внизу «Читаю внешние отчёты и обработки из ‹база› для сверки с Git». Успешно выгруженные расширения считаются после получения файлов. |
| Долгие операции и ожидание | «~48%» выглядело как доля готовых файлов. При неизвестной длительности появлялось «ещё немного». | Процент по длительности подписан «по времени». Для измеренной работы видны числитель и знаменатель. При отсутствии оценки и подробностей показано «Длительность пока неизвестна». |
| Выбор версии гейта | В ручном подтверждении установки на кнопке было «True». В PowerShell значение попало в позиционный параметр подписи. | Кнопки «Установить» и «Отмена». Нажатие Enter при открытии окна выбирает отмену. |
| Решение по комплекту после жёлтого или красного прогона | После Esc оператор узнавал, что комплект остался в тестовой базе. | Последствие Esc видно до выбора. Загруженный комплект остаётся в базе, эталон сохраняется прежним. |

## Десять замечаний по остальным экранам

| Где | Что видел оператор | Что теперь видно |
|---|---|---|
| Рабочая база → Откат | Название «Откатить рабочую базу» обещало восстановление всей базы. | Пункт «Откатить изменения выпуска» открывает выбор выпуска. Подтверждение называет базу и выпуск, перечисляет объекты для восстановления, снятия регистрации и пропуска. По умолчанию выбрана «Отмена». [Выбор состава отката](../gate/deploy.ps1) |
| Приёмка поставки → Ожидание CI | Полоса заполнялась по лимиту ожидания, даже если проверка стояла в очереди. | Видны номер PR, прошедшее время, название проверки и лимит ожидания. [Ожидание проверки поставки](../gate/delivery.ps1) |
| Ночное задание | Описание в планировщике обещало прогон «как есть» при любом исходе сверки с Git. | В описании указаны оба режима. В меню и выводе задания видны фактический режим и коммит при загрузке из Git. Отдельно отмечается пропущенный запуск. [Регистрация и запуск задания](../gate/nightly.ps1) |
| Пустая история откатов | В списке можно было выбрать откат последнего выпуска. | Пояснение «У гейта пока нет сохранённых выпусков для отката» и одна кнопка «Назад». [История откатов](../gate/deploy.ps1) |
| Опасный пункт с подтверждением | Подсказка обещала выбор одним щелчком. | Маркер ▲ и подсказка заранее объясняют повторный щелчок. После выделения можно подтвердить выбор мышью или Enter. [Подсказки и обработка мыши](../src/ci-tui/dialog.go) |
| Шапка и история прогона | Код завершения выглядел как отдельная поломка. При отсутствии файла вердикта история приписывала прогону остановку. | Шапка показывает вердикт, код записан в журнал. В истории при отсутствии результата указано «Вердикт недоступен». В подробностях приведена причина остановки, если она записана, и путь к журналу, если он сохранился. [Шапка](../src/ci-tui/model.go) · [История](../gate/run.ps1) |
| Копирование журнала | Надпись F2 обещала весь журнал, хотя начало могло выпасть из буфера окна. | Сообщение указывает число скопированных строк. После вытеснения начала оно уточняет, что это последние 6000 строк окна. Для операций с журналом выводится путь к файлу. [Копирование](../src/ci-tui/model.go) |
| Выгрузка типовой | Подпись git add описывала внутреннюю упаковку. Следом шёл ещё один шаг упаковки. | «Подготовить файлы к коммиту (git add)», затем «Упаковать объекты перед отправкой (git repack)». [План выгрузки](../gate/deploy.ps1) |
| Настройки → Проверка входа | Оператор узнавал про демонстрационный исход уже после запуска клиента. | Пункт «Демонстрация экрана проверки входа» заранее поясняет, что откроется клиент тестовой базы и результат демонстрационный. [Настройки](../gate/settings.ps1) |
| Прогноз всего прогона | Время со знаком «+» скрывало, сколько шагов ещё без статистики. | Экран показывает прогноз по известным шагам и отдельно указывает число шагов без оценки. В узком окне прогноз виден над журналом. [Расчёт и вывод времени](../src/ci-tui/pipeline.go) |

## Остальные проверенные маршруты

| Маршрут | Что оператору уже помогает |
|---|---|
| Установка, запуск, обновление гейта | Установщик называет целевую папку. При выборе релиза видны установленная, более новая и более старая версии. После установки есть отдельное сообщение о перезапуске. [Установка](../install.ps1) · [Релизы](../gate/update.ps1) |
| Тестовая база, комплект из входящих, продолжение | В меню разделены прогон текущего состояния, загрузка комплекта и продолжение. В результатах повторно использованного шага указан исходный прогон. При занятом конфигураторе поясняется, что произойдёт с несохранёнными правками. [Меню и продолжение](../gate/run.ps1) |
| Поставки, сверка с Git, приёмка отдельных файлов | Итог связывает поставку, коммит, объекты и прогон. Для файла, принятого целиком, отчёт перечисляет выполненные проверки и ограничения проверки содержимого. [Отчёт поставки](../gate/delivery.ps1) |
| Подготовка, применение, доступ, блокировки | При подготовке указано, что пользователи продолжают работу. При закрытии входа поясняется судьба существующих сеансов, при сбое снятия запрета указано, где проверить состояние базы. [Обновление](../gate/deploy.ps1) · [Блокировки](../gate/locks.ps1) |
| Модульные тесты, самопроверка и формы 1С | В каталоге тестов поясняется, что статус взят из последнего прогона. В форме входа демонстрация помечена в самом результате. Действия после обновления сообщают этап и пишут подтверждение выполнения. [Каталог и прогон](../gate/run.ps1) · [Формы](../epf) · [Проверка результата действий](../gate/post-update.ps1) |
| Отчёты, эталоны, время, публикация | Разбор ошибки предлагает следующее действие. Результаты прогона показывают решение по комплекту. В статистике указаны план и факт, в опубликованной папке пояснено назначение report.txt, summary.txt и run.log. [Разбор ошибок](../gate/report.ps1) · [Длительности](../gate/stats.ps1) · [Публикация](../gate/publish.ps1) |

Проверка понятности с операторами на реальных задачах остаётся отдельной работой. При повторной приёмке попросите оператора по одному экрану назвать базу, последнее завершённое действие и последствия Enter или Esc.
