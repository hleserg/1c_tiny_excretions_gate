# Что видит оператор гейта

Аудит от 27 ноября 2026 года. Исходная версия ядра — `605fbb9`. Проверены подписи меню, диалогов и журналов по коду их обработчиков. Для экрана сверки с Git, решения по комплекту и ручного обновления есть воспроизводимые сценарии на подставной 1С. Остальные выводы ниже основаны на чтении кода. Рабочую базу для аудита не обновляли.

## Что исправлено

| Где | Что видел оператор | Что теперь видно |
|---|---|---|
| Сверка перед загрузкой из Git | После трёх выгрузок расширений слева появлялось «3/3, 100%». Внизу шла ещё одна выгрузка. | Слева «Расширения выгружены · 3 из 3». Внизу «Читаю внешние отчёты и обработки из ‹база› для сверки с Git». Успешно выгруженные расширения считаются после получения файлов. |
| Долгие операции и ожидание | «~48%» выглядело как доля готовых файлов. При неизвестной длительности появлялось «ещё немного». | Процент по длительности подписан «по времени». Для измеренной работы видны числитель и знаменатель. При отсутствии оценки и подробностей показано «Длительность пока неизвестна». |
| Выбор версии гейта | В ручном подтверждении установки на кнопке было «True». В PowerShell значение попало в позиционный параметр подписи. | Кнопки «Установить» и «Отмена». Нажатие Enter при открытии окна выбирает отмену. |
| Решение по комплекту после жёлтого или красного прогона | После Esc оператор узнавал, что комплект остался в тестовой базе. | Последствие Esc видно до выбора. Загруженный комплект остаётся в базе, эталон сохраняется прежним. |

## Что стоит исправить дальше

Приоритет определён по последствию для оператора. Сначала идут формулировки, по которым можно неверно оценить изменение базы или принять решение во время ожидания.

| Приоритет и место | Что можно понять неверно | Предлагаемая подпись или изменение |
|---|---|---|
| Высокий · Рабочая база → Откат | «Откатить рабочую базу» обещает восстановление всей базы. Код выбирает расширения и обработки конкретного выпуска, учитывает наличие копий и отдельно сообщает о пропусках. | В меню «Откатить изменения выпуска». До подтверждения одним списком показать выпуск, базу, что вернётся и что останется. [Выбор состава отката](../gate/deploy.ps1) |
| Высокий · Приёмка поставки → Ожидание CI | Полоса «CI PR» получает в качестве ожидаемой длительности весь лимит ожидания. Половина лимита может пройти, пока проверка ещё в очереди. | «Жду проверку PR №… · прошло 05:00 · лимит ожидания 30 мин». Долю выполненной проверки показывать, только если её сообщает CI. [Ожидание проверки поставки](../gate/delivery.ps1) |
| Высокий · Ночное задание | В планировщике описание обещает прогон «как есть». При настроенном репозитории гейт сначала проверяет Git и при подходящих условиях запускает прогон с обновлением тестовой базы. | В описании задания указать оба режима. В итоговой строке назвать фактический режим и коммит при загрузке. [Регистрация и запуск задания](../gate/nightly.ps1) |
| Средний · Нет истории откатов | Красная строка «ОТКАТИТЬ ПОСЛЕДНИЕ ИЗМЕНЕНИЯ» доступна для выбора даже при пустой истории. Выбор возвращает в то же меню. | «У гейта пока нет сохранённых выпусков для отката». Оставить действие «Назад». [Экран истории](../gate/deploy.ps1) |
| Средний · Подтверждение опасного пункта мышью | Общая подсказка обещает выбор одним щелчком. Для отмеченных опасных действий первый щелчок только выделяет пункт, второй подтверждает. | Заранее помечать пункты с повторным подтверждением. После первого щелчка окно уже предлагает щёлкнуть ещё раз или нажать Enter. [Обработка мыши и подсказки](../src/ci-tui/dialog.go) |
| Средний · Шапка и история прогона | «Завершился с кодом 2» рядом с жёлтым вердиктом выглядит как ещё одна неисправность. «Нет итога (остановился до вердикта)» также выводится при отсутствии прочитанного вердикта. | Для законченного прогона выводить вердикт первым, код оставить в журнале. Для отсутствующего итога писать «Вердикт недоступен», а причину брать из журнала. [Шапка](../src/ci-tui/model.go) · [История](../gate/run.ps1) |
| Средний · Копирование журнала | «F2 журнал в буфер обмена» копирует сохранённые в окне строки. У длинного прогона это последние 6000 строк. Начало может понадобиться для разбора ошибки. | При достижении лимита писать «Скопированы последние 6000 строк окна». Для прогона рядом дать путь к полному run.log. [Буфер окна](../src/ci-tui/model.go) |
| Средний · Выгрузка типовой | «git add (файлы — в pack)» описывает способ хранения, а назначение операции приходится угадывать. Следом идёт ещё одна операция упаковки. | «Подготовить файлы к коммиту (git add)», затем «Упаковать объекты перед отправкой (git repack)». [План выгрузки типовой](../gate/deploy.ps1) |
| Низкий · Настройки → Показать канарейку | В пункте выбора сказано «временно: открыть её в temp». Оператор узнаёт про случайный исход демонстрации уже после запуска клиента. | «Демонстрация экрана проверки входа». Подсказка «Откроется клиент тестовой базы. Результат демонстрационный». [Режим демонстрации](../gate/settings.ps1) |
| Низкий · Прогноз всего прогона | В записи «осталось ~12:34+» знак плюса означает, что для части шагов пока нет статистики. Из самой надписи это трудно понять. | «Осталось около 12 мин по известным шагам. Без оценки ещё 2». Проверить перенос в узкой колонке. [Расчёт и вывод времени](../src/ci-tui/pipeline.go) |

## Остальные проверенные маршруты

| Маршрут | Что оператору уже помогает |
|---|---|
| Установка, запуск, обновление гейта | Установщик называет целевую папку. При выборе релиза видны установленная, более новая и более старая версии. После установки есть отдельное сообщение о перезапуске. [Установка](../install.ps1) · [Релизы](../gate/update.ps1) |
| Тестовая база, комплект из входящих, продолжение | В меню разделены прогон текущего состояния, загрузка комплекта и продолжение. В результатах повторно использованного шага указан исходный прогон. При занятом конфигураторе поясняется, что произойдёт с несохранёнными правками. [Меню и продолжение](../gate/run.ps1) |
| Поставки, сверка с Git, приёмка отдельных файлов | Итог связывает поставку, коммит, объекты и прогон. Для файла, принятого целиком, отчёт перечисляет выполненные проверки и ограничения проверки содержимого. [Отчёт поставки](../gate/delivery.ps1) |
| Подготовка, применение, доступ, блокировки | При подготовке указано, что пользователи продолжают работу. При закрытии входа поясняется судьба существующих сеансов, при сбое снятия запрета указано, где проверить состояние базы. [Обновление](../gate/deploy.ps1) · [Блокировки](../gate/locks.ps1) |
| Модульные тесты, самопроверка и формы 1С | В каталоге тестов поясняется, что статус взят из последнего прогона. В форме входа демонстрация помечена в самом результате. Действия после обновления сообщают этап и пишут подтверждение выполнения. [Каталог и прогон](../gate/run.ps1) · [Формы](../epf) · [Проверка результата действий](../gate/post-update.ps1) |
| Отчёты, эталоны, время, публикация | Разбор ошибки предлагает следующее действие. Результаты прогона показывают решение по комплекту. В статистике указаны план и факт, в опубликованной папке пояснено назначение report.txt, summary.txt и run.log. [Разбор ошибок](../gate/report.ps1) · [Длительности](../gate/stats.ps1) · [Публикация](../gate/publish.ps1) |

Проверка понятности с операторами на реальных задачах остаётся отдельной работой. При повторной приёмке попросите оператора по одному экрану назвать базу, последнее завершённое действие и последствия Enter или Esc.
