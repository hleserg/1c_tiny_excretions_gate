# Разработка

## Что нужно

- Windows с PowerShell 5.1 — для скриптов и тестов (`gate/`).
- Go 1.24.7 или новее — для `ci.exe`, подставной 1С и сборщика.
- Для работы с обработками — конфигуратор 1С. Выгрузка обработки в файлы (`epf/`), загрузка: «Файл → Открыть» выгрузку или `/LoadExternalDataProcessorOrReportFromFiles`.

## Локальная проверка

Из корня репозитория в Windows PowerShell 5.1 запусти разбор скриптов Windows PowerShell 5.1 и проверку сборки в памяти.

```powershell
.\gate\check.cmd
.\build.cmd -check
```

Для тестов с подставной 1С собери обе программы в каталог, из которого их берёт тестовый скрипт. Параметр `-C` у Go задаёт каталог модуля.

```powershell
go -C src/fake1c build -o ../../gate/test/fake1c.exe .
go -C src/merge1c build -o ../../gate/test/merge1c.exe .
.\gate\test.cmd
```

Для выборочного прогона передай часть имени сценария, например `.\gate\test.cmd -Only git-typical`. Итог записывается в `gate/test/last-run.txt`. Чтобы проверить свой пакет, запусти `.\build.cmd -private <полный-путь-к-площадке> -check`.

При изменении поведения добавь описание в `gate/readme.txt` и строку истории в разделе 9 с меткой `@@ВЕРСИЯ@@`. Перед слиянием проверь результаты Windows-тестов, `go vet` и `go test` всех четырёх модулей и анализа BSL. [Workflow CI](../.github/workflows/ci.yml)

## Версии

Штамп сборки — `ГГГГММДД.ЧЧММСС` по UTC+3. В исходниках на его месте метка `00000000.000000`, в скриптах — `Версия 00000000.000000.`, в руководстве — `@@ВЕРСИЯ@@`. Сборщик проверяет число меток и подставляет штамп. Релиз — тег `vГГГГММДД.ЧЧММСС`: CI соберёт архивы и приложит их к релизу.

## Пометки в коде 1С

Каждая правка в BSL помечается строкой `// ** Фамилия И.О. ГГГГММДД что и зачем`. У блока такая же строка ставится в начале и в конце, со словом «конец». Чужие пометки не трогаются.

## Ревью от Codex

Работают два способа, можно включить оба.

1. **Codex в облаке.** В настройках Codex на chatgpt.com подключи репозиторий и включи code review. После этого Codex сам ревьюит PR, а по комментарию `@codex review` — по запросу. Правила ревью он берёт из раздела «Review guidelines» в [AGENTS.md](../AGENTS.md).
2. **GitHub Action** (`.github/workflows/codex-review.yml`). Добавь секрет `OPENAI_API_KEY` в настройках репозитория. Workflow на каждый PR запускает `openai/codex-action` и публикует ревью комментарием. Без секрета задача пропускается и не падает.

## Приватные пакеты площадки

Пакет своей базы лежит в отдельном приватном репозитории. Там же — свои `config.psd1`, эталоны и заметки. Сборка из корня ядра принимает полный путь к репозиторию площадки через `-private`. В публичный репозиторий имена площадки не попадают, AGENTS.md это проверяет на ревью.
