# Правила для агентов (Codex, Claude и др.)

Репозиторий — гейт расширений 1С: PowerShell 5.1 (`gate/`), Go (`src/`), BSL и выгрузки обработок в XML (`epf/`, `packages/`). Отвечать и писать комментарии — по-русски.

## Как проверить изменения

- `build.cmd -check` — собрать обработку «Выполнить после обновления» с пакетами в памяти (метки, маршруты, XML).
- `gate\check.cmd` — разбор всех скриптов PowerShell 5.1 без запуска.
- `gate\test.cmd` — тесты гейта с подставной 1С. Команды сборки `fake1c.exe` и `merge1c.exe` в нужный каталог приведены в [инструкции разработчика](docs/development.md).
- `go vet ./...` в каждом модуле `src/*`.

## Жёсткие правила (нарушение — блокирующее замечание)

1. Гейт никогда не работает с рабочей базой: проверка имени тестовой базы и `ForbiddenBases` не ослабляются.
2. Расширения удаляются только по имени (`/DeleteCfg -Extension <имя>`), ключ `-AllExtensions` с удалением — никогда.
3. Сеансы завершаются только у базы с точным именем; блокировки, которые поставил скрипт, снимаются в конце в любом исходе (`finally`/`trap`). Исключение одно, по решению владельца репозитория (20.11.2026): «Закрыть базу» (`deploy.ps1 -CloseBase`). До завершения сеансов его блокировки тоже снимаются в `finally`; после - остаются по замыслу, записаны в файл закрытия (`deploy\close\closed-<база>.json`) и снимаются только `-OpenBase`, только свои. Новых исключений без такого же решения нет.
4. Пароли — только файлами DPAPI (`ConvertFrom-SecureString`), в логах и выводе — `***` вместо `/P` и `/UC`.
5. Типовая конфигурация не меняется; правки — в расширениях и внешних обработках.
6. В публичный репозиторий не попадает ничего про конкретную площадку: имена серверов, баз, организаций, людей, номера ТЗ, заводские расширения. Это — в приватном репозитории площадки (`-private`).

## PowerShell 5.1

- Файлы `.ps1`/`.psd1` — UTF-8 с одним BOM, CRLF; `.cmd` — только ASCII.
- `Set-StrictMode -Version 2.0`: необъявленная переменная — авария; проверять ветки, где переменная может не появиться.
- Регулярные выражения с `\$(` — только в одинарных кавычках (в двойных PowerShell выполнит `$(...)`).
- `@($ordered[$key])` на значении-List падает («Argument types do not match») — перебирать через конвейер.
- `ui.ps1` и `stats.ps1` подключаются точкой: их `$script:` переменные не должны совпадать с ключами и переменными верхнего уровня `run.ps1`/`deploy.ps1`/`settings.ps1` (сборщик это проверяет).
- Совместимость с Windows PowerShell 5.1: без операторов `??`, `?.`, тернарного `? :` и прочего из PowerShell 7.

## BSL (обработки)

- Код — по стандартам 1С (https://its.1c.ru/db/v8std). Замечание к коду 1С — со ссылкой на стандарт (`#stdNNN`) и место.
- Каждая правка помечается комментарием автора: `// ** Фамилия И.О. ГГГГММДД что и зачем`; у блока — такая же строка в конце со словом «конец». Чужие пометки не переписывать.
- Нельзя `Новый X(...).Метод()` — сначала в переменную. Не называть переменные `Строка`, `Символ`, `Тип`, `Формат`; в модуле формы — `Объект`, `Документы`.
- Ядро (`epf/ВыполнитьПослеОбновления`) обращается к пакетам только через маршруты, которые пишет сборщик (метки `// @@ПАКЕТЫ: ...@@`). Ядро не называет объекты конкретной базы.
- Пакет — `packages/<Имя>`: функции-крючки с суффиксом имени пакета (`ПакетПодходит<Имя>` обязательна), см. `docs/packages.md`. Тексты записей журнала (`ЗаписатьОшибку` и т.п.) не менять без нужды: по ним гейт сравнивает прогон с эталоном.
- Тесты пишут в базу только в транзакции, которая отменяется, и только если `ЗаписьРазрешена()`.

## Review guidelines

На ревью смотреть в первую очередь:

- нарушения жёстких правил выше — это P0;
- ошибки PowerShell 5.1: StrictMode, кодировка, кавычки в регулярках, перехват ошибок, освобождение COM, ветки без ответа пользователя (ci.exe `-UiChannel` и консоль);
- изменения откатов и блокировок: в любом исходе база возвращается к понятному состоянию;
- изменение текстов записей самопроверки и ключей заданий: это ломает сравнение с эталоном у всех, кто уже работает;
- заводские имена в публичных файлах;
- обновлён ли `gate/readme.txt` (руководство и строка истории в разделе 9), если меняется поведение гейта, и есть ли тест в `gate/test/tests.ps1` на новый сценарий.

Мелочи оформления — одним списком в конце, без блокировки.
